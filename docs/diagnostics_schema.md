# StackVet Machine-Readable Diagnostics Schema

This document defines the stable diagnostic schema and source location conventions used by StackVet for CI/CD integrations, GitHub Code Scanning, and IDE tooling.

## 1. Schema Versioning & Compatibility

StackVet adheres to Semantic Versioning for its diagnostic data interchange format:

| Schema Property | Current Version | Compatibility Guarantee |
|---|---|---|
| `schema_version` | `"1.0.0"` | Additive, backward-compatible evolutions retain major version `1`. Breaking alterations bump major version. |

### Compatibility Rules
- **Deserializer Resilience**: Consumers must ignore unrecognized keys to permit seamless schema evolution.
- **Backward Compatibility**: Reports produced without `schema_version`, `tool`, or `summary` deserialize cleanly using sensible defaults.
- **Explicit Missing Data**: When a check evaluates workspace-wide state (such as missing `Dockerfile` or `pyproject.toml`), physical file locations are explicitly omitted (`normalized_path() == None`, SARIF `locations: []`, table display `"-"`) rather than fabricating line 1 positions.

## 3. Source Location & Code Context Conventions

### Line and Column Conventions
- **1-based Indexing**: All line and column numbers are 1-indexed. The first character on the first line of a file is at `(line: 1, col: 1)`.
- **Unicode Awareness**: Column numbers count Unicode characters (scalar values / code points) rather than raw UTF-8 byte offsets. Multi-byte UTF-8 sequences (such as emojis or CJK characters) occupy 1 character column.
- **Cross-Platform Path Normalization**: All paths use forward slashes (`/`) and strip Windows UNC prefixes (`\\?\`).
- **Multiline Statement Spans**: For imports or expressions spanning multiple lines, `start_line` and `start_col` mark the beginning of the statement or alias, while `end_line` and `end_col` mark its terminus.

## 4. SARIF v2.1.0 Format (`--format sarif`)

StackVet generates OASIS SARIF v2.1.0 compatible reports for GitHub Code Scanning and IDE SARIF viewers:

- **Rule Catalog Registration**: The `runs[0].tool.driver.rules` array registers metadata for all rules evaluated, including rule title, description, remediation help, category tags, and default severity level.
- **Physical Locations & Regions**: Each result provides `physicalLocation.artifactLocation.uri` and detailed `region` bounds (`startLine`, `startColumn`, `endLine`, `endColumn`, and `snippet`).
- **Related Locations**: Circular import hops, multi-file cycles, or duplicate import sites populate `relatedLocations`.
- **Automated Fixes**: When automated remediation is available, the SARIF `fixes` array specifies `fileChanges` and `replacements` targeting the relevant file and deleted region.
