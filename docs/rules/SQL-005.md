# SQL-005: Legacy SQLAlchemy 1.x session.query() syntax

| Attribute | Value |
|-----------|-------|
| **Rule ID** | `SQL-005` |
| **Category** | `framework` |
| **Default Severity** | `WARNING` |

## Description
Using legacy session.query(...) instead of modern SQLAlchemy 2.0 select() and session.scalars().

## Why This Matters
Detecting and addressing legacy sqlalchemy 1.x session.query() syntax prevents runtime failures, dependency conflicts, or configuration drift in production environments.

## Remediation
Migrate from 'session.query(User).filter(...)' to 'session.scalars(select(User).where(...))'.

## Configuration & Suppression
To suppress this rule for a specific file or line, add an inline comment:

```python
# stackvet:ignore SQL-005
```

Or configure a rule override in `.stackvet.toml`:

```toml
[rules]
"SQL-005" = "off" # or "warning", "error"
```
