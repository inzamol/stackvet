# FAP-016: Sensitive field exposure in schema

| Attribute | Value |
|-----------|-------|
| **Rule ID** | `FAP-016` |
| **Category** | `framework` |
| **Default Severity** | `ERROR` |

## Description
Pydantic model schema exposes sensitive password/secret fields without Field(exclude=True) or response filtering.

## Why This Matters
Detecting and addressing sensitive field exposure in schema prevents runtime failures, dependency conflicts, or configuration drift in production environments.

## Remediation
Mark sensitive fields with 'Field(exclude=True)' or create a separate output schema (e.g. UserResponse).

## Configuration & Suppression
To suppress this rule for a specific file or line, add an inline comment:

```python
# stackvet:ignore FAP-016
```

Or configure a rule override in `.stackvet.toml`:

```toml
[rules]
"FAP-016" = "off" # or "warning", "error"
```
