# SEC-002: Stale vulnerability advisory database cache

| Attribute | Value |
|-----------|-------|
| **Rule ID** | `SEC-002` |
| **Category** | `security` |
| **Default Severity** | `WARNING` |

## Description
Vulnerability analysis was performed using a local cache that has exceeded its configured time-to-live (TTL).

## Why This Matters
Security advisories are published continuously. Analyzing dependencies against an expired advisory cache can fail to detect newly disclosed CVEs, leading to unpatched security vulnerabilities in production.

## Remediation
Run with `--refresh-vuln-cache` or verify internet access to update the local advisory database. In CI/CD pipelines, ensure the runner can contact the vulnerability database or refresh the cache artifact periodically.

## Configuration & Suppression
To suppress this rule for a specific file or line, add an inline comment:

```python
# stackvet:ignore SEC-002
```

Or configure a rule override in `.stackvet.toml`:

```toml
[rules]
"SEC-002" = "off" # or "warning", "error"
```
